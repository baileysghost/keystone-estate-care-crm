# Deployment and operations

Use the existing Keystone Vercel project and Supabase project. Apply the additive migrations in order after migration 004. Migration 005 initializes ingestion as disabled and grants the existing server database role access to the private integration tables. Migration 006 restricts creation of Supabase identities to enabled email addresses in employee_access. Run 006 only in the dedicated Keystone authentication project. Bootstrap the first administrator by inserting the approved email and administrator role into keystone.employee_access using the database owner.

Set DATABASE_URL (or POSTGRES_URL), SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, CRM_ORIGIN and HERMES_API_KEY server-side. Private file uploads also use SUPABASE_SERVICE_ROLE_KEY. Keep the previous CRM_WORKSPACE_PASSWORD available for rollback. Set the Supabase Auth Site URL to the production CRM and add the exact /login callback URL to the allowed redirects. Require email confirmation. The administrator enters their approved email and a new password of 12 or more characters at /login and selects Activate invited account. Confirm the email, then sign in. To authorize another employee use Settings → Employee access. Disabling a member immediately denies protected reads and writes. Password recovery is available on the sign-in page.

Generate a secret with openssl rand -hex 32 on a trusted device or with your password manager. Store matching copies as HERMES_API_KEY in Vercel server environments and in the Hermes secret store. To rotate, pause ingestion, set the new value, redeploy the intended environment, update Hermes, verify /health rejects the old key and accepts the replacement, then resume ingestion. Never send the value in chat or paste it into the repository.

Use npm ci, npm test, npm run lint, npm run typecheck and npm run build. Verify /api/crm is inaccessible anonymously, exercise administrator and employee permissions, and confirm a real email activation and password reset before enabling external ingestion. Review recent runs from Hermes Activity. Turn ingestion off in Settings for immediate containment. Delete only the separate fictional dataset using Settings → Remove fictional examples.

For rollback, pause ingestion, restore the last known-good Vercel deployment, and keep the new tables intact. Older deployments use their original shared workspace password. Rolling back the application does not roll back schema or employee records. Back up any new data before removing integration tables or the registration trigger.
